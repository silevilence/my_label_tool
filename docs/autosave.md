# 自动保存与恢复

侧栏常驻显示当前自动保存模式与状态；点击「设置自动保存」打开独立弹窗，修改后点击「应用设置」生效，取消或 Esc 不更改设置。设置只保存在本机，提供三个互斥模式：

- **不开启**（默认）：完全手动保存；关闭窗口、切换项目遇到未保存修改时询问是否放弃。
- **定时保存**：间隔为 10–3600 秒，默认 60 秒；没有变化时不重复写入。
- **切换图片时自动保存**：保存刚离开的图片；脚本、预打标、撤销等对其他图片的修改也会触发保存。

自动保存写入本机原生工作副本，不覆盖 YOLO、COCO 等导出文件。工作副本包含标签、完整标注、属性、原图像素坐标与视频源帧号；尚未完成的绘制草稿和撤销历史不包含在内。首次开启会建立现有数据的完整基线，此后按变化图片提交；不为保存读取原图尺寸或解码所有图片。手动保存成功后也会更新工作副本，因此自动保存关闭时仍能恢复最近一次手动保存的数据。

定时保存包含当前图片已经完成的操作。拖动、缩放尚未结束时，保存上一次提交的几何；操作结束后的版本仍会等待下一次保存。保存期间可以继续编辑，旧版本写入完成不会把新修改误记为已保存。手动保存与后台保存串行协调；同一保存目标的重复请求合并，「保存」与「另存为」分别排队。请求使用点击时的格式、目标和数据快照，排队期间显示状态并禁用导出格式切换；后续编辑仍进入恢复副本。

正常关闭窗口或切换项目时，开启自动保存会补存剩余修改；失败则保留窗口与内存数据，侧栏提供重试。异常退出只能恢复最近一次成功提交的数据。重新启动时可选择「继续上次标注」；重新打开原图片目录也会提供恢复提示。恢复提示提供「取消」「保留副本并读取原项目」「恢复工作副本」；取消/Esc 不替换当前项目。选择读取原项目后，后续保存先保留旧副本的完整文件，再建立新基线。损坏或无法读取的副本也可选择保留原始文件并尝试打开原项目。导入失败会回退原项目的图片、标注、历史和配置，原恢复会话继续工作。正常关闭的编辑门禁一直保持到原生窗口销毁完成。缺失的图片会跳过并报告数量。

F5、Ctrl+R 及强制刷新组合已保留，不能用于标签或动作改绑。Windows 宿主关闭 WebView2 浏览器加速键，前端另有捕获阶段保护；输入框和弹窗中也不会因这些按键刷新标注界面。

## 存储与开发约定

- 位置：应用数据目录的 `recovery/<项目绝对目录摘要>/`，不向原图片目录写入，不参与插件或 MCP 契约。移动项目目录后不会自动关联旧路径的副本。
- `head.json` 版本为 1，指向已提交片段范围；片段保存图片相对路径的替换/删除与同批标签、项目配置元数据。没有首次导出配置的项目也可恢复。
- 数据片段先写到同目录临时文件并同步，再原子替换；最后原子更新 head。未提交片段不参与恢复，写入失败保留原 head；每个项目带预期修订号；根目录文件锁串行化不同进程的读取、修订号检查、提交与压缩，拒绝过期写入。发生冲突时可选择「保留双方副本并继续保存」，保留磁盘版本并提交当前完整标注，不要求关闭或丢弃内存修改。
- 每 128 个片段在 Rust 后台合并，提交新 head 后清理旧片段；恢复仅重放已提交范围。文本读取统一经宿主读取适配器，不绕过受控环境的读取方式；超过适配器单文件 64 MiB 限制的基线/片段按 UTF-8 字符边界分为 `.txt` 数据块，再用 `schemaVersion: 2` 的片段清单引用；每块不超过读取上限，旧的单文件片段仍可读取。缺块或坏块明确失败，不返回部分标注。
- 读取原项目、冲突处理、损坏副本重建时，旧文件复制并同步到 `recovery/archives/<项目摘要>/copy-*/`，保留原始字节且不自动清理。设置弹窗可打开保留副本目录；这些目录用于保留与排查，不会自动合并到当前标注。
- 前端跟踪逐图修改版本，切图保存不枚举全项目标注；基线和批量变更需要处理其涉及的数据。删除最后一条标注提交空数组，移除图片提交删除记录。
- 恢复副本使用 `recovery-copy` 操作资源；正常状态只在侧栏显示，错误仍进入操作面板。MCP 控制期间暂停后台触发，收回控制后补存，保持原控制权约束。
- 新增 `load_recovery`、`save_recovery`、`last_recovery_project`、`fork_recovery`、`open_recovery_directory` 仅供宿主前端调用；没有更改 `AnnotationShape`、`LabelConfig`、`ProjectConfig` 或插件 API/协议版本。
