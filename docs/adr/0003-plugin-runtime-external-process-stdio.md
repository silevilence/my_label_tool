# 代码型插件经外部进程 + stdio NDJSON 接入，WASM 留作协议扩展

插件系统 v1 中所有代码型插件（导出格式、外部预打标程序）都以独立外部进程运行，宿主与插件通过 stdio 上的 NDJSON（每行一个 JSON 消息）通信；未采用 WASM 运行时，也未采用 JSON-RPC 2.0。原因：任意语言零成本接入（能读写 stdin/stdout 即可），OS 级隔离与超时杀进程，stderr 日志天然可诊断，且仓库已有外部进程编排先例（`.pt` 转换的 yolo CLI / uvx 路径）。进度事件、取消控制、配置迁移需要头等消息类型与插件域错误码，JSON-RPC 2.0 需大量规范外扩展。协议信封与宿主 API 版本独立编号，消息携带 `runtime` 字段，未来 WASM 可作为新 runtime 值接入而不破坏协议。

**Status**: accepted

**Considered Options**
- WASM 运行时：沙箱更细、启动更快，但当前 Tauri 技术栈无现成 WASM 宿主链路，任意语言支持打折，调试/日志工具链弱
- JSON-RPC 2.0：规范现成，但进度/取消/迁移均为临时扩展，错误码体系需映射插件域语义
- 两者并行：能力最强，但框架范围翻倍，v1 拖延

**Consequences**
- 每次调用都伴随进程生命周期管理（启动、冷却复用、超时杀进程）
- 插件生态的最低门槛是能读写 stdin/stdout；WASM 接入点在协议层预留，不影响现有插件
