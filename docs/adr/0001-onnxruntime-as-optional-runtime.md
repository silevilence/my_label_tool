# ONNX Runtime 作为可选运行时组件，不随安装包分发

预打标功能需要 ONNX Runtime 推理运行时（`onnxruntime.dll`，约 40-90MB），直接打包会冲击“体积小、启动快”的核心定位。决定：DLL 不随安装包分发，作为可选的运行时组件——应用首次使用预打标时检测 app data 目录下约定路径，缺失则引导用户从项目 GitHub Release 资源下载（用户确认后），或手动下载放置到该路径，放置后即时识别无需重启。Rust 端使用 `ort` crate 的 `load-dynamic` 特性动态加载，构建期不下载任何二进制。

**Status**: accepted

**Considered Options**
- 随安装包打包：安装包 +40~90MB，违背体积核心诉求
- 前端 `onnxruntime-web`（WASM）：核心包轻量，但单线程推理慢 3~5 倍，WebView2 下线程受限
- `tract` 纯 Rust 推理：无外部 DLL，但 YOLOv8/v11 算子覆盖有兼容风险
- 可选下载/手动放置（选定）：核心包保持轻量，推理功能按需启用，离线用户可手动获取

**Consequences**
- 预打标功能默认不可用，需用户主动获取运行时；UI 必须提供清晰引导（缺失检测、下载入口、放置路径提示）
- 运行时版本需与 `ort` crate 兼容；发布流程需在 Release 附带 DLL 资源并带校验（如哈希），避免损坏下载
- 下载是联网且用户显式确认的一次性行为，不违背“运行期离线”原则；获取后即完全离线可用
