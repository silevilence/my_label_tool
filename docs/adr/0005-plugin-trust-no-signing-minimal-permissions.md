# 插件 v1 信任基线：无代码签名、权限最小化、宿主代理数据访问

插件 v1 不做代码签名校验，安装弹窗明示「未验证作者、运行任意代码」警告；信任建立在「权限最小化 + OS 进程隔离 + 宿主代理」上：权限面仅 `fs.read` / `fs.write`（目录级授予）与 `network`（默认拒绝），`spawn` 权限不开放，插件访问项目数据一律经宿主协议中转，未授权路径返回 `PERMISSION_DENIED`。Windows 代码型插件必须运行在 AppContainer 中，只给插件包、声明使用的系统解释器运行目录只读/执行权限与协议 stdio 句柄；v1 不授予网络 capability。宿主环境按白名单重建，禁止把 token、密钥与代理变量继承给插件。环境变量离线标志不构成安全边界，AppContainer 初始化失败时必须拒绝启动。原因：签名体系需要证书管理、发布流程与 UI，与离线轻量定位冲突；权限模型在 v1 收紧比事后收紧成本低得多。

**Status**: accepted

**Considered Options**
- v1 即做代码签名：需要公钥管理、签名流程与校验 UI，范围显著增大
- 开放 spawn：允许插件再拉子进程，风险面大且难以审计

**Consequences**
- 插件生态扩大后可在协议层追加签名校验（新字段 + 校验步骤），不破坏现有插件
- 数据型插件（预置标签）无执行风险，安全模式下保留；代码型插件在安全模式全部禁用
- AppContainer profile 每次进程启动独立创建，启动失败或进程结束时撤销临时 ACL 并清理；
  直接包外文件读取、宿主秘密环境变量与 socket 连接必须有可复现的对抗测试
