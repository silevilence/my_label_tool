# 插件 v1 信任基线：无代码签名、权限最小化、宿主代理数据访问

插件 v1 不做代码签名校验，安装弹窗明示「未验证作者、运行任意代码」警告；信任建立在「权限最小化 + 宿主代理」上：权限面仅 `fs.read` / `fs.write`（目录级授予）与 `network`（默认拒绝），`spawn` 权限不开放，插件访问项目数据一律经宿主协议中转，未授权路径返回 `PERMISSION_DENIED`。原因：签名体系需要证书管理、发布流程与 UI，与离线轻量定位冲突；权限模型在 v1 收紧比事后收紧成本低得多。

**Status**: accepted

**Considered Options**
- v1 即做代码签名：需要公钥管理、签名流程与校验 UI，范围显著增大
- 开放 spawn：允许插件再拉子进程，风险面大且难以审计

**Consequences**
- 插件生态扩大后可在协议层追加签名校验（新字段 + 校验步骤），不破坏现有插件
- 数据型插件（预置标签）无执行风险，安全模式下保留；代码型插件在安全模式全部禁用
