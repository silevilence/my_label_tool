# 当前编辑对象与其作用域归属标注 store

「当前图片」及其浏览作用域（项目序 / 搜索结果 / 单个视频的帧序）移入 `useAnnotationStore`，删除与接续、标注清理、历史裁剪在同一次原子更新内完成；作用域是可压栈的有序集合，栈顶决定「上一张 / 下一张 / 下一个未标注」，并且必须常驻可见、可退出。这条同时修订 `AGENTS.md §6` 的分层表述：画布瞬时交互态（缩放、平移、绘制中图形、交互模式）仍留在组件本地，但**当前编辑对象及其作用域属于业务数据**，进 store——它与标注清理、导出、批处理共享同一份事实。

**Status**: accepted（`AGENTS.md §6` 措辞随批次 ④ 的实现一起修订）

**Considered Options**
- 新建 `useProjectStore`：边界更干净，但删除流程要跨两个 store 协调，原子性需要额外保证
- 状态留在 `App.tsx`，只把索引数学抽成纯模块：改动最小，但 11 个写入点仍各自持有序列表与夹取逻辑——这正是当前漂移的来源

**Consequences**
- 删除后接续不再依赖调用方自觉：`useImageDeletion` 的 `remaining[Math.min(index, remaining.length - 1)]` 在 `index = -1` 时把选择清空（画布变白）这类缺陷在原子更新内消失
- 搜索不再是「一次性跳转」：确认后进入结果集作用域，侧栏出现可见的作用域条与退出方式
- 视频帧步进与图片步进成为同一作用域模型的两个实例，`ProjectMediaList` 的 `remembered` 影子游标与搜索对话框的私有游标随之删除
