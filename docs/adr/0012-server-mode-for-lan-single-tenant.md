# 服务端形态：单租户局域网、核心先行、与桌面形态并存

在桌面形态之外新增服务端形态：一个进程同时提供命令 API、图片端点与静态前端，浏览器作为客户端，服务器本地目录即项目存储；单租户（不设计租户隔离），身份为服务端本地的用户名 + 口令。传输层由新的 HTTP 层承担——Tauri 2 不存在受支持的 headless 模式（wry 要求事件循环与窗口句柄，官方 headless 指 `xvfb-run` 跑 GUI），命令层的 Rust 业务逻辑整体复用，耦合点仅 `AppHandle`（路径解析）与 `Channel`（事件汇），前端只有 5 个原语需要抽象。并发以 HTTP 前置条件 ETag / If-Match 做整文档乐观锁（冲突回 412），因为项目文档是单文件整覆写，多人同存必然丢更新。桌面形态保留（§1 的离线定位），两形态共用同一前端与核心逻辑，差异只落在桥接层。实施分两阶段：先做与平台无关的核心（桥接层、HTTP 传输、账号、工作区白名单、并发控制、任务注册表），宿主平台后定——Linux 容器要额外承担三项替换：删图改软删除（非 Windows 现在是刻意的 fail-closed）、DirectML 退 CPU、代码型插件因无沙箱等价物而不可用。插件在服务端：数据型（`label-preset`）始终启用，代码型仅 Windows 宿主且管理员显式开启。操作归属发起用户，发起者可取消自己的、管理员可取消任意，浏览器断线不取消。预打标为全局模型库 + 全局运行时 + 服务端推理队列（并发上限可配）。

**Status**: accepted

**Considered Options**
- 保留 Tauri 窗口并以外部传输驱动 `invoke`（headless GUI）：IPC 与 ACL 语义可原样保留，但依赖官方标注为不稳定且无示例的 API（`Context::new`、`webview::InvokeRequest`），失败面不可控
- 服务端替代桌面形态（单形态）：维护面最小，但放弃离线定位，且受控环境（ADR 0011）仍需要本地程序
- 浏览器上传图片到服务端存储：网络与存储模型全改，单租户局域网下收益不明显
- 共享口令或无认证：省一张账号表，但任务归属、取消权与冲突提示都失去主语
- 平台先行（先定 Windows 宿主或 Linux 容器）：把平台取舍绑进核心设计，与平台无关的桥接层、并发与任务模型反被推迟

**Consequences**
- 前端 5 个原语与 Rust 侧两个耦合点成为唯一分岔处；其余代码两形态共用，新功能默认要同时满足两种形态
- 项目目录必须位于服务端配置的工作区根目录内：`assetProtocol.scope = ["**"]` 等价的能力不得带入服务端，目录白名单取代桌面态的任意路径选择
- 长任务语义两形态不同（桌面关窗即取消，服务端断线继续），需要显式任务注册表；现有 `static BUSY` 不足以表达归属与跨用户可见性
- 预打标在服务端成为共享资源：一份模型库、一份运行时、一份内存预算，多人并发时排队
- Linux 宿主下形态不对等（无回收站删除、无 GPU 加速、无代码型插件），必须在界面与文档中如实说明，不得静默降级
- 桥接层存在两项只能靠原型回答的未知：脱离 webview 驱动命令层时 capabilities/ACL 是否仍生效、`Channel` 到 SSE/WebSocket 的投递契约（阻塞、缓冲、背压、关闭行为）
