# 脚本以「作用域快照 + 分块执行 + 缓冲 + 原子写回」为事务边界

一次脚本运行是一次整体事务：前端按作用域栈顶分块推送图片与标注快照，宿主进程内的 Lua 通过本地脚本命令读写（取图片集、读标注、提交结果、上报进度、写日志），提交只登记结果；全部图片处理成功后才一次性写回 store（一条撤销记录），取消或任一图片失败则标注零变化。写入面为覆盖式：提交过的图片整表覆盖其标注，未提交的图片不动，不设追加模式，也不走细粒度操作流。原因：运行期就地写回的话，取消或出错会留下「项目一半改过一半没改」的中间态，而预打标「保留已完成结果」的先例在这里不适用——它生成新标注，脚本改写既有标注；分块执行买到的是进度与内存，不是取消粒度，取消由终止宿主进程实现。

**Status**: accepted

**Considered Options**
- 就地写回 + 保留已完成结果：与预打标体验一致，但中间态难以解释，还要额外定义单图容错语义
- 返回操作或变更集：差异天然可审计，但脚本需构造操作序列，且要定义操作顺序、同图形多操作与 id 引用语义
- 真反向 RPC（脚本命令回问主进程与前端、惰性拉取）：真惰性，但新增协议方向，前端在运行中途充当服务端，并与切图、改标注、预打标争夺状态

**Consequences**
- 运行期占用「项目标注」操作资源，与预打标、导出等互斥；运行期间 store 不变，用户既有操作不受干扰
- 结果缓冲区即「先看差异再应用」的预览数据；默认跑完即应用，完成报告给可核对数字（图片数、图形增删改、跳过数）并带撤销入口
- 脚本的处理对象是作用域栈顶的图片集合，不设独立的「整个项目」开关；视频帧路径按普通图片路径处理，不做特殊化
- 图片尺寸不进默认快照（逐图解码，代价等同一次保存），需要时由运行前的显式选项带入
