# 操作注册表与按资源互斥

长任务（导出、预打标、视频抽帧、模型与运行时下载、保存、删除）统一向一个操作注册表登记：登记时声明名称、占用的资源与取消句柄，界面按操作读取进度、取消与终态。并发允许，但占用同一资源的操作互斥，裁决只发生在 `canStart(resource)` 一处；消息按操作归属并带类型，不再由「最后写入者」决定用户看到哪一条。

**Status**: accepted

**Considered Options**
- 全局串行（任何长任务在跑时禁用其他长任务入口）：最好解释，但边导出边预打标是合理用法，且「什么算长任务」仍需枚举
- 只做归属、不声明资源：改动最小，但把互斥策略留在原处——今天它是 `workspaceDisabled`、键盘门禁、`canDeleteImage` 三个各自计算的与运算，加上写三遍的视频导入锁表达式

**Consequences**
- 现状 22 个 hook 级状态槽与两条会被覆盖的提示通道（5 秒红框 / 2.2 秒琥珀条）退化为一个注册表；成功消息不再借用错误通道与错误配色
- 取消成为操作的属性：界面上「哪里能取消」不再由各组件自行决定（当前更新下载没有任何取消入口）
- 后续 MCP 接入的「控制权、长任务进度查询与取消」可直接落在同一注册表上，而无需另建一套任务状态
