# 插件 API 版本与弃用策略

插件版本、宿主 API 版本、协议版本与插件清单结构版本彼此独立。主程序版本
不参与插件契约协商，也不得在主程序发版时顺手递增以下版本。

## 版本基线

| 版本面          | 当前版本 | 宿主支持版本 | 弃用中 | 已移除 |
| --------------- | -------: | ------------ | ------ | ------ |
| 宿主 API 整体   |        1 | 1            | 无     | 无     |
| exporter 能力   |        1 | 1            | 无     | 无     |
| prelabel 能力   |        1 | 1            | 无     | 无     |
| NDJSON 协议     |        1 | 1            | 无     | 无     |
| manifest schema |        1 | 1            | 无     | 无     |

插件清单通过 `apiVersion.min` 声明整体宿主 API 的目标版本；exporter 与
prelabel 可分别通过 `capabilities.<name>.apiVersion.min` 声明目标版本，缺省时
继承整体目标版本。宿主按目标版本分派实现，不从版本号推断插件能力。协议版本
不进入插件清单，随 `hello` 调用协商。

## 兼容性规则

- 同一版本号内只允许增量兼容变更，例如新增可选字段、新错误码或新协议方法。
- 新增字段必须可选并提供默认值；禁止删除字段、改变既有字段语义或重排必需字段。
- 破坏性变更必须为受影响的版本面建立新版本；不相关的版本面保持不变。
- 宿主 API 整体与 exporter、prelabel 能力分别维护支持版本集合。
- 协议信封或消息形状发生破坏性变更时只递增协议版本。
- 插件清单结构发生破坏性变更时只递增 `schemaVersion`。

## 弃用流程

宿主 API 的旧实现按以下顺序退出：

1. 标记为 `deprecated`，记录受影响能力与目标替代版本。
2. 提供替代实现及迁移说明。
3. 保持至少两个后续宿主 API 版本的兼容期。
4. 兼容期结束后移除旧实现，并在上方版本表记录移除历史。

声明已移除目标版本的插件在安装协商或启动握手时收到
`API_VERSION_UNSUPPORTED`，错误原因必须包含所需版本、宿主支持版本和升级建议。
该流程遵循 [ADR 0007](adr/0007-plugin-api-target-version-dispatch.md)。
