# 脚本（Lua 数据处理）

> 状态：可开工。决策依据 ADR 0013（宿主进程与信任边界）、ADR 0014（写回事务）、ADR 0015（能力面扩展）；术语见 `CONTEXT.md`「脚本 (Scripting)」段。

## Problem Statement

用户手里已经有一整套标注，想对它做批量处理——批量改派标签、统一裁到图内、跨图去重、按规则修正坐标——但现有三条路都不合适：

- **手工逐图改**：几百张图起就没有可行性。
- **导出 → 自己写脚本处理文件 → 重新导入**：要保存、要来回走文件格式、还会丢标签映射与项目上下文；而这一步本来是纯内存操作。
- **写插件**：为一时的数据处理需求走打包、安装、授权、启用流程，代价与收益完全不成比例。

用户真正缺的能力是：**在这个工具的内存态上直接做数据变换**，改动立即能在画布上核对，并且**是否落盘仍由用户自己决定**。

## Solution

在应用内提供「脚本」：用 Lua 写一段数据变换，选定作用域后运行，主程序把作用域内的图片与标注分块交给一个独立的脚本宿主进程；脚本通过脚本命令读写数据，把结果提交回主程序。全部图片处理成功后，结果一次性写回内存——**一次运行等于一条撤销记录，是否保存仍由用户决定**；取消或任一图片失败则标注零变化。

脚本存机器级脚本库，应用内即改即跑；运行是一项可在界面上取消的操作，占用「项目标注」资源，完成时给出可核对的统计。

## User Stories

1. 作为标注者，我想在应用内写一段 Lua 变换并立刻看到结果，以便不必把标注导出、改完再导入。
2. 作为标注者，我想在处理前选定作用域（整个项目序 / 搜索结果 / 某个视频的帧序），以便只改我要改的那部分。
3. 作为标注者，我想在脚本运行时看到进度并随时取消，以便发现写错时立刻停手。
4. 作为标注者，我想让取消的结果是标注零变化，以便不用收拾一个改了一半的项目。
5. 作为标注者，我想在跑完后看到可核对的统计（处理了多少张图、图形改了多少、新增多少、删除多少、跳过多少），以便确认脚本干的正是我想要的。
6. 作为标注者，我想用一次撤销回退整轮脚本运行，以便后悔时一步回到原样。
7. 作为标注者，我想在不确定时先看差异再决定是否应用，以便对别人给的脚本保留一道闸。
8. 作为标注者，我想把某个标签的框批量改派到另一个标签，以便修正系统性标错。
9. 作为标注者，我想按数值规则批量调整坐标与尺寸（统一裁到图内、按比例缩放、修掉越界），以便处理系统性偏差。
10. 作为标注者，我想写跨图逻辑（全局去重、按图片分组统一编号），以便处理单张图看不出来的问题。
11. 作为标注者，我想让脚本对不符合条件的图片不做任何改动，以便只处理我要处理的那部分数据。
12. 作为标注者，我想在没有标注的图片上安全跳过，以便不必为脏数据写特判。
13. 作为标注者，我想在脚本失败时看到出错的图片与原因，以便定位问题而不是靠猜。
14. 作为标注者，我想让失败表现为「整轮不写回」，以便修好脚本再重跑，而不是修补残局。
15. 作为标注者，我想把脚本存在应用里、随时改随时跑，以便迭代规则时不必反复挑文件。
16. 作为标注者，我想把脚本导出成文件、也从文件打开，以便备份、比版本或发给同事。
17. 作为标注者，我想让脚本运行期间的界面保持可用，以便长任务不阻塞我继续标注。
18. 作为标注者，我想在运行时被告知它与预打标、导出等操作互斥，以便理解为什么某个入口不可用。
19. 作为标注者，我想让脚本只能接触图片清单与标注、碰不到我的文件与网络，以便放心运行别人给的脚本片段。
20. 作为标注者，我想让取数据这一步不被「逐张解码图片尺寸」拖累；需要尺寸时再显式带上，以便大项目上也能快速开跑。
21. 作为标注者，我想在视频项目的帧序里跑脚本且行为与图片一致，以便不必为视频学第二套用法。
22. 作为同事，我想确认脚本永远不会随项目文件被自动执行，以便安全地交换项目文件。
23. 作为受控环境（终端透明加密）用户，我想让脚本库文件与其它配置一样经读取适配器读取，以便脚本功能不受加密策略影响。
24. 作为维护者，我想在新增一项脚本能力时只改一处注册表加一个实现，以便这个功能能长期长能力而不失控。
25. 作为维护者，我想让脚本运行作为一项操作登记、占用「项目标注」资源，以便互斥与消息归属沿用既有模型而不是另起一套。
26. 作为服务端形态用户，我想脚本在服务端也能用，且不可用时被明确告知，以便不踩「桌面能跑、服务端悄悄不能」的坑。

## Implementation Decisions

**执行形态**

- 脚本由**独立宿主进程**执行（ADR 0013）：宿主是应用自带的二进制，与主程序只交换「请求 / 响应 / 进度 / 取消」的最小 NDJSON 协议，复用既有进程原语（进程组、Job Object、进程终止）；不进入插件注册表、安装授权流程、安全模式与版本面。
- 宿主进程**零文件、零网络能力**：数据只经协议进出，脚本碰不到项目文件与图片文件本身。脚本库文件由主程序读，不经宿主。
- Lua 隔离基线：只加载安全子集标准库（无 `io` / `os` / `package` / `debug`），只接受文本 chunk（拒绝二进制字节码），配合宿主内存上限、总超时与单图超时、取消即终止进程。
- 信任边界为「只防手滑」：不自动发现、不自动执行任何来源的脚本；项目配置永不携带脚本内容。若将来开放脚本分发、项目自带脚本自动运行或服务端任意用户提交脚本，必须先升级隔离等级（ADR 0013）。

**能力面**

- 脚本命令以**命令注册表**集中声明：命令名、参数、返回、错误语义与所需数据段落登记在一处；新增能力只改注册表加一个实现，不引入第二条数据通路（ADR 0015）。
- v1 命令面（单一命名空间，窄而明确）：列出图片集、读取指定图片的标注、提交指定图片的结果、上报进度、写日志；另暴露 API 版本常量供脚本判断兼容。未知命令返回可识别的错误，而不是静默无操作。
- 数据面**按段落传输**（图片与标注为首个段落），协议带版本字段与启动协商，只做增量字段扩展、容忍未知字段。
- 能力扩展分三档并明示代价：①只依赖快照的能力——加一个命令实现即可；②需要宿主新数据的能力——增加一个快照段落；③需要宿主动作或惰性拉取的能力（读写文件、保存、导出、调用预打标）——必须新增「宿主 → runner 请求」方向，属大改，须先开 ADR，v1 不做。

**运行事务**（ADR 0014）

- 一次脚本运行是一次整体事务：按**作用域栈顶**取快照 → 分块执行 → 结果缓冲 → **全部图片成功后一次性写回**（一条撤销记录）。取消或任一图片失败 → 标注零变化。
- 写入面为**覆盖式**：提交过的图片整表覆盖其标注，未提交的图片不动；不设追加模式，不走细粒度操作流。新图形由主程序补 `id`；提交结果做结构、`labelId` 与数值合法性校验，校验失败按该图片失败处理。
- 处理对象是作用域栈顶的图片集合，不设独立的「整个项目」开关；视频帧路径按普通图片路径处理，不做特殊化。
- 运行期占用「项目标注」资源，与预打标、导出等互斥。
- 图片尺寸**默认不进快照**（逐图解码，代价等同一次保存）；需要时由运行前的显式选项带入。

**前端接入与界面**

- 写回复用既有批量写入接口与分组机制（同一分组跨多次写入合并为一条历史），**不新增 store 接口**。
- 完成报告给可核对数字（图片数、图形增删改、跳过数）并带撤销入口；提供「先看差异再应用」开关（默认关，缓冲区即预览数据）。报告走操作注册表的消息归属，不自建提示通道。
- 脚本库为机器级持久化（应用数据目录、一脚本一份 `.lua` 加轻量索引），提供列出、新建、重命名、删除，以及从文件打开与导出到文件；编辑器内未保存也可运行。
- 脚本库是新的宿主文本读路径：复用既有文本读写命令，**不新增第二条读取路径**；写入侧保持原生，受控环境下保存成败以写入调用返回为准（ADR 0011）。
- 资源上限比照既有资源限制模式：机器级配置、校验与执行共用、默认值集中；数值默认值待原型实测后确定。
- 用户可见文案进 i18n 结构；Rust 侧错误文案进既有 Rust 文案模块。

**契约影响**

- 新增 Tauri 命令面，按 `AGENTS.md` §10 完成边界影响评估：结论为**不影响插件契约**——不改 manifest schema、不改协议与宿主 API 版本、不新增插件能力。脚本协议是产品内部协议，不对外公开，不纳入插件 Schema 体系。

## Testing Decisions

**什么样的测试算好**：只断言外部可观察的行为——脚本能不能读写数据、取消后标注是否零变化、失败是否整轮不写回、报告数字是否正确、撤销是否一次回退整轮；不断言内部调用顺序、不断言协议字段的逐字形状、不为「有测试」而测桩。

**两个新测试缝**（其余全复用既有缝）：

1. **Rust 侧：runner 的协议循环**——进程编排、分块推送、结果缓冲、上限与取消。用**桩宿主进程 + 集成测试**，复用 `plugin_conformance` 的桩进程模式（先例：插件协议一致性测试）。覆盖正常运行、超时、取消、宿主崩溃、行上限、契约违规。
2. **前端侧：脚本运行编排的纯逻辑模块**——作用域快照构建、分块调度、结果缓冲合并、统计与报告计算。用 Vitest，api 调用按预打标执行 hook 测试的既有方式隔离（先例：预打标批量执行的 hook 测试）。

**复用既有缝，零新增**：写回走既有批量写入 + 分组；互斥走操作注册表；脚本库读写走既有文本读写命令；进程原语走既有进程控制模块；面板验收测试照插件管理 UI 的验收测试写法。

**宿主二进制自身**：cargo 单元测试覆盖命令面与沙箱，含对抗用例——尝试 `io` / `os` / `require`、提交二进制 chunk、死循环、巨量分配，全部须报错或被终止。

**手动验证清单**（画布交互相关，改动涉及界面时必须过）：跑一个真实脚本后画布、图片列表与统计一致；缩放后标注框仍与图片对齐；导出文件与界面状态一致；一次撤销回退整轮。

## Out of Scope

- **反向 RPC / 惰性拉取**（脚本命令回问主程序或前端，按需取数据）——属能力扩展第三档，须先开 ADR。
- **脚本分发与自动执行**：脚本市场、随项目携带并自动运行、服务端任意用户提交脚本。
- **追加模式与细粒度操作流**（变更集/操作列表形式的写入面）。
- **第三方 Lua 模块生态**（`require` 加载外部库）与脚本读写文件、读取图片像素。
- **与 MCP 的整合**：MCP 是独立立项（见 ROADMAP），脚本宿主不为其预留专用通道。
- **视频专用脚本语义**：帧路径按普通图片处理，逐帧批处理的专用能力另行立项。

## Further Notes

- **待原型确定的两项**：Lua 方言（倾向标准 Lua 5.4：脚本作者最熟悉、可用本机解释器调试；Luau 的硬内存上限在「只防手滑」的边界下不是必需）与具体数值上限（宿主内存、总超时、单图超时，实测后定默认值）。
- **打包与交付**：宿主二进制要覆盖桌面打包与容器交付；任一形态不可用时必须在界面如实说明，不得静默降级（ADR 0012 的既有要求）。
- **快捷键**：默认不提供；若提供，只提供「打开脚本面板」这类无副作用动作并纳入快捷键设置面板。
- **文档同步**：规格落地后同步更新 `AGENTS.md` 的命令清单、目录结构与文档索引，并按 `plugin-api-versioning` 的核对清单确认插件契约面未变更。
- **配套文档**：`docs/scripting.md`（本文件）为开发者规格；面向用户的命令清单与示例脚本随实现一并交付。
