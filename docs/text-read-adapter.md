# 宿主文本读取适配器

适用于本机离线读取，以及由终端透明加密策略保护的文本。入口：侧边栏菜单「设置」中的「文本读取适配器」。默认是原生模式，无需安装 Python。

## 配置

| 模式 | 适用条件 | 配置 |
| --- | --- | --- |
| 原生 | 本工具可直接读取明文 | 无额外字段 |
| Python | IT 已允许指定 Python 解释器读取目标文件 | Python 解释器的绝对路径，或 PATH 中的程序名 |
| 命令 | 已有可信的本机批量读取程序 | 可执行文件 + JSON 参数数组 |

1. 选择模式并填写字段，设置超时（100–300000 毫秒，默认 30000）。Windows 只接受 EXE；优先填绝对路径。
2. 点「预览读取命令」。界面展示解析后的程序路径和实际参数；Python 模式展示宿主内置脚本。修改任一字段后必须重新预览。
3. 点「重新自检」检查草稿，或点「自检并保存」检查并应用。宿主写出含中文、é、🌍、CRLF/LF 的临时 `.txt`，使用该模式读回逐字比对。成功后配置才生效；失败保留原配置。
4. 重试之前失败的操作，无需重启。此前因读取失败而未恢复的标签、快捷键、模型库和打开的脚本库会重新加载；已成功加载的内容和编辑草稿保留。

设置中显示最近一次自检的模式与结果。每次启动后的首次实际读取，以及切换配置后的首次实际读取，都会再次自检。同一会话自检失败后，后续读取立即阻断，直至在设置中重新自检或保存成功。自检通过只验证当时临时文件的可读性，具体项目路径/扩展名还需按 IT 策略验证。

Windows 配置存储在当前用户的 `HKCU\Software\my_label_tool\TextReadAdapter` 的 `Config` 值中。它是本机用户设置，不进入项目文件，也不依赖受控文本读取，因此读取模式失效后仍可打开设置修复。非 Windows 开发宿主使用 `$HOME/.my-label-tool-text-reader` 启动配置文件，该文件必须处于透明加密策略之外。

## 命令模式协议

宿主直接启动配置的可执行文件，将参数数组逐项传入，不拼接命令行脚本、不展开占位符、不调用 shell。文件路径通过 stdin 传递，避免 Windows 命令行长度限制：

```json
{"paths":["C:\\project\\一.txt","C:\\project\\二.xml"]}
```

stdin 在请求发送完后关闭。程序必须在 stdout 返回一个 **UTF-8 JSON 字符串数组**，数量、顺序与输入路径相同，然后正常退出。例如：

```json
["第一份内容\r\n","<annotation>第二份内容</annotation>"]
```

不要在 stdout 输出日志、BOM 或进度；诊断写入 stderr。一次批次的 stdin 上限 8 MiB、stdout 上限 64 MiB、stderr 上限 64 KiB。任一文件失败时整个批次失败，宿主不提交部分标注结果。UTF-8 无效、JSON 类型或数组长度错误、超限、非零退出及超时均失败，不回退原生读取。

以下是符合协议的本机 Python 命令程序示例（按 IT 要求放在受信任目录）：

```python
import json
import sys

request = json.load(sys.stdin)
contents = []
for path in request["paths"]:
    with open(path, "rb") as source:
        contents.append(source.read().decode("utf-8"))
sys.stdout.buffer.write(json.dumps(contents, ensure_ascii=False).encode("utf-8"))
```

配置程序为解释器绝对路径，参数数组如 `["-I","-X","utf8","C:\\trusted\\read_batch.py"]`。也可使用任何满足此协议的本机 EXE。宿主内置 Python 模式不需要这个文件，不会下载或安装依赖。

## 读取范围与写入语义

- 标签文件、导入来源、项目配置、视频清单及 ffprobe 文本输出。
- 应用数据目录下的标签、模板、快捷键、模型库、资源限制、脚本库索引与 Lua 源码。
- 插件清单、标签预置、注册表及设置。插件 `fs.read` 的 UTF-8 请求在既有目录授权、链接检查与句柄路径检查之后使用适配器；Windows 读取期间持有禁止修改/删除的文件句柄，代理超时会取消外部读取。二进制 Base64 请求仍按原契约读取字节。

图片、视频、ONNX、DLL、ZIP、可执行文件检查与包完整性哈希是二进制读取，不经过文本适配器。插件能力、manifest schema、宿主 API 与协议版本均保持 v1，插件不能配置或直接调用适配器。Lua 命令与协议保持不变。

写入仍由宿主原生执行。受控环境下「写入后回读校验」不成立，保存成败以写入调用返回为准；自检是模式可用性检查，不作为普通文件保存的附加成功条件。

批量 YOLO/VOC 导入对同一目录的全部标签文件一次读取，不逐文件启动程序。稳定配置下一批启动一次外部程序；会话首次使用额外启动一次自检程序。取消入口位于操作进度卡片，自检也可在设置内取消；Windows 使用 Job Object，超时、取消和退出会终止整个进程树。

## 排障

| 现象 | 操作 |
| --- | --- |
| 找不到程序 | 检查解释器/EXE 的绝对路径，重新预览；不要填 `type` 等 shell 内建命令或 `.bat` |
| 自检内容不一致、非法 UTF-8 | 检查 IT 是否允许该程序读取目标文件，确认 DLP 策略是否收紧；命令须按 UTF-8 输出，不能混入日志 |
| 超时 | 检查程序是否在等待终端交互、协议是否正确，按文件体积调整超时；可取消后修复配置 |
| 自检成功但项目读取失败 | 核对项目目录、扩展名、文件权限和文件编码；临时目录与项目目录可能适用不同策略 |
| 注册表配置损坏 | 在设置中重新选择模式，预览、自检并保存；已有项目数据保持原样 |

不建议把通用解释器或 shell 加入全局解密白名单，也不建议使用带 `-Command`、`/c` 的 shell 包装来读取拼接路径。使用 IT 明确批准的最小范围程序与目录。受控环境的核实由使用者/IT 按[核实清单](verification/dlp-encrypted-text-read-adapter.md)执行，不是开发前置条件。

## 扩展实现

注册表位于 `src-tauri/src/text_read/adapters.rs`。新增模式实现 `Adapter` 的 `metadata`、`plan` 与 `read`，并在 `ADAPTERS` 中登记；字段描述驱动设置界面与配置校验，共用 Unicode 自检、进程执行、错误处理与会话生命周期。调用方只依赖 `text_read::read` / `read_many`，无需改动。前端不枚举模式 ID。
