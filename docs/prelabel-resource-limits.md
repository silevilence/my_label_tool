# 预打标资源限制

在侧栏菜单的「设置 → 预打标资源限制」中配置并保存：

- **预打标最大内存占用（MiB）**：默认 80 MiB，只约束 ONNX 输出张量与宿主的一份输出副本。
- **预打标最大原始候选框数量**：默认 100000，指置信度过滤前、所有输出张量合计的数量。

模型管理顶部显示当前预算及换算后的最大输出元素数量。输出为 f32，每个元素按运行时输出 4 字节 + 宿主副本 4 字节合计 8 字节计算：

`最大输出元素 = floor(内存预算 MiB × 1024 × 1024 ÷ 8)`

80 MiB 对应 10485760 个元素。标准 YOLOv8 2560×2560、80 类的输出为 11289600 个元素和 134400 个原始候选框；设置 128 MiB、150000 个候选框即可通过这两项资源校验。通过资源校验不保证模型推理一定成功。

这不是整个进程的硬内存配额：模型权重、运行时中间层、图片预处理、候选框对象及显存均不在这个预算内。提高预算需考虑本机可用资源。NMS 仍保留最高 30000 个候选框参与处理，最多返回 300 个结果；输入尺寸和源图片解码保护独立保留。

配置保存在应用数据目录的 `prelabel-resource-limits.json`，不进入项目或模型库。文件缺失以及新增字段缺省时使用默认值，非法值或文件损坏明确报错；保存采用临时文件与替换，保存失败不发布新配置。数值必须为正整数，前后端使用相同的安全整数表示边界，不按机器内存强行钳制。

读取失败后可在设置中点击「填入默认值」，再点击「保存资源设置」修复配置；不会自动覆盖损坏文件。保存失败保留草稿，重新读取前会确认是否丢弃未保存的修改。

每次模型校验及推理调用开始时由后端读取已保存配置。会话缓存键包含两个上限，变更后下一次调用重建会话；进行中的单次调用使用开始时的快照。多次调用组成的批量任务在下一次调用使用新配置。推理前检查模型声明输出；推理后、复制任何输出之前，再检查全部实际输出形状。后一道检查不能阻止 ONNX Runtime 自身已发生的内存分配。

## 宿主与插件边界

TypeScript `PrelabelResourceLimits` 和 Rust 同名类型字段对应。新增宿主命令 `load_prelabel_resource_limits` / `save_prelabel_resource_limits`，前端统一经 `lib/tauri-api.ts` 调用。原有预打标命令参数和结果保持兼容。

设置只应用于宿主内置 ONNX 管线，未向插件开放命令或底层能力，也不限制外部插件进程。插件的预打标协议、Schema、权限、宿主 API 与协议版本均无变更。
